# PIKU 채굴풀 + 현물/선물 거래소

PoW 코인 **PIKU**를 채굴하는 **마이닝 풀**과, 채굴한 코인을 거래하는 **현물·채굴량 선물·무기한 선물 거래소**를 하나의 웹 서비스로 묶은 프로젝트입니다.

- 기본값은 **테스트 모드**입니다. KRW는 가상 잔고이고, 가입하면 가상 1억 KRW가 지급되며 상단에 테스트 모드 배너가 표시됩니다.
- **실자금 모드**는 환경변수 `REAL_MONEY_MODE=true`로만 켤 수 있습니다. 필수 요건(아래 참고)이 빠져 있으면 모든 프로세스가 기동을 거부합니다.

> ⚠️ 실자금 운영 전에 반드시 [실자금 모드 전 확인사항](#실자금-모드-전-확인사항)을 읽으세요. 특히 **자기가 발행한 코인을 자기 거래소에 상장하는 구조**는 국내법상 큰 쟁점입니다.

## 구성

```
                 ┌──────────── web (nginx + React) :8000 ────────────┐
 브라우저 ───────▶│  /api, /ws → api                                  │
                 └──────────────────────────────────────────────────┘
                              │ REST/WS
                     ┌────────▼────────┐  Redis Stream(명령)   ┌──────────────┐
                     │  api (Fastify)  │ ───────────────────▶ │ engine (단일) │  ← 모든 거래 상태 변경을 순서대로 처리
                     │  인증/2FA/조회    │ ◀─────────────────── │ 매칭/콜옥션    │     (주문·취소·체결·청산·펀딩·만기정산)
                     └────────┬────────┘   응답/이벤트(Pub/Sub) │ 청산/펀딩/정산 │
                              │                                └──────┬───────┘
                     ┌────────▼───────────────────────────────────────▼──┐
                     │                 PostgreSQL / Redis                 │
                     └────────▲───────────────────────────────▲──────────┘
 채굴기 ── Stratum :3333 ──▶ stratum (쉐어 검증, PPLNS)       worker (입출금, 블록 성숙, 핫월렛 대사)
                              │ getblocktemplate/submitblock          │ getnewaddress/sendtoaddress/...
                              └──────────────▶ PIKU 노드 (JSON-RPC, compose 미포함) ◀──┘
```

| 프로세스 | 역할 |
|---|---|
| `engine` | 가격-시간 우선 매칭 엔진. Redis 스트림의 명령을 **한 번에 하나씩** 처리하고, 명령 하나를 PostgreSQL 트랜잭션 하나로 반영합니다. Redis 리더 락으로 **단일 인스턴스**를 강제합니다. 콜옥션, 강제청산(2초마다), 펀딩(8시간마다), 채굴량 선물 만기 정산도 같은 직렬 큐에서 실행합니다. |
| `api` | REST + WebSocket. 상태 변경 요청은 엔진으로 보내고 결과를 기다립니다. 조회는 DB/Redis에서 직접 읽습니다. |
| `stratum` | Stratum V1 서버. getblocktemplate으로 작업을 만들고, 쉐어를 검증하고, 블록을 찾으면 submitblock 후 PPLNS로 분배합니다(미성숙 상태). |
| `worker` | 입금 감지/컨펌, 승인된 출금 전송, 풀 블록 100컨펌 확인 후 보상 확정, 핫월렛 대사 알림을 담당합니다. |
| `web` | React SPA를 nginx로 서빙하고 `/api`, `/ws`를 api로 프록시합니다. |

## 실행 방법

### 1) docker-compose (노드 제외 전체)

```bash
cd piku-exchange
cp .env.example .env
# .env 수정: RPC_HOST/RPC_PORT/RPC_USER/RPC_PASSWORD, JWT_SECRET, ADMIN_EMAILS
docker compose up -d --build
```

- 웹: http://localhost:8000
- Stratum: `stratum+tcp://<서버>:3333`
- `ADMIN_EMAILS`에 넣은 이메일로 가입하면 관리자 계정이 됩니다. 이 계정은 **운영자 플래그**도 켜져 있어 PIKU를 거래할 수 없습니다.
- 노드에 연결할 수 없어도 거래소 기능(가입, 거래, 선물)은 동작합니다. stratum은 노드가 연결될 때까지 재시도하고, worker는 오류를 로그로 남기고 계속 실행됩니다.

### 2) 로컬 개발

```bash
# PostgreSQL 16, Redis 7 필요
cd backend && npm install
export DATABASE_URL=postgres://piku:piku@localhost:5432/piku REDIS_URL=redis://localhost:6379 ADMIN_EMAILS=admin@example.com
npm run dev:engine     # 엔진 (마이그레이션 자동 실행) — 먼저 띄울 것
npm run dev:api        # :8080
npm run dev:stratum    # :3333 (노드 필요)
npm run dev:worker     # (노드 필요)

cd ../frontend && npm install && npm run dev   # http://localhost:5173 (/api, /ws 프록시)
```

### 3) 코인 노드

stratum과 worker는 **비트코인 코어 호환 JSON-RPC**를 사용합니다. 사용하는 RPC는 `getblocktemplate`, `submitblock`, `getbestblockhash`, `getmininginfo`, `getblock`, `getnewaddress`, `getaddressinfo`, `validateaddress`, `listsinceblock`, `gettransaction`, `sendtoaddress`, `getbalances`입니다.

- 기본 알고리즘은 **SHA-256d**입니다. Scrypt나 RandomX를 쓰려면 `src/core/stratum/`의 헤더 해시 함수와 난이도 1 기준값을 바꿔야 합니다. RandomX는 Stratum 프로토콜 자체가 달라서(XMRig 방식) 서버 재작성이 필요합니다.
- 앞서 만든 **Python 학습용 PowCoin은 이 노드 요구사항을 충족하지 않습니다.** 단일 프로세스이고 RPC/getblocktemplate이 없습니다. 실제 PIKU 노드는 비트코인 코어 포크로 만드는 것이 일반적입니다.
- 노드 없이 풀을 시험하려면 `bitcoind -regtest -rpcuser=piku -rpcpassword=...`로 대체할 수 있습니다. regtest는 난이도가 매우 낮아 CPU 채굴기로도 블록이 바로 나옵니다.

## 기능 요약

### 1. 마이닝 풀
- 접속 ID는 `거래소아이디.워커이름`이고 비밀번호는 무시합니다. 채굴 보상은 **거래소 계정 잔고로 바로 적립**됩니다.
- 쉐어는 vardiff(목표 15초/쉐어), 중복 쉐어 거부, 오래된 작업 거부, ntime 범위 검사, version-rolling(ASICBoost) 마스크 검사를 거칩니다.
- **PPLNS**: 블록을 찾은 시점의 최근 쉐어를 난이도 합 N(= 네트워크 난이도 × 2)만큼 모아 비례 분배합니다. 풀 수수료는 1%이고, 반올림 잔액은 수수료 계정으로 갑니다.
- 블록 보상은 **100컨펌 전에는 '미성숙'** 으로 표시되고, 100컨펌 후 확정 잔고로 전환됩니다. 고아 블록이 되면 분배를 취소합니다.
- 대시보드에는 내 해시레이트(10분/1시간/24시간), 워커별 상태(온라인·난이도·수락/거부), 예상 일일 채굴량, 누적 채굴량, 미성숙 보상, 네트워크 난이도·해시레이트가 표시됩니다.
- 접속 안내 페이지(`/pool/guide`)에 ASIC, cpuminer, cgminer 예시 명령어가 있습니다.

### 2. 지갑
- 입금 주소는 `getnewaddress`로 발급하고, `listsinceblock`으로 입금을 감지합니다. 6컨펌 후 잔고에 반영합니다.
- 출금은 **OTP 필수** → 잔고 잠금 → **관리자 승인 큐** → worker가 `sendtoaddress`로 전송합니다. 실패하면 잔고를 되돌리고 알림을 남깁니다. 전송 중 프로세스가 죽으면 이중 전송을 막기 위해 `sending` 상태로 남기고 관리자 확인 알림을 보냅니다.
- 사용자에게 받은 출금 수수료와 실제 네트워크 수수료의 차액은 수수료 계정이 부담하므로 장부가 정확히 맞습니다.
- **핫월렛 대사**는 1분마다 실행합니다. 노드 잔고(확정+미확정+미성숙)를 장부 기대치(전체 PIKU 잔고 + 미반영 입금 + 미성숙 블록 보상)와 비교해, 차이가 허용치를 넘으면 관리자 알림을 남깁니다.

### 3. 상장 단계
`PRE_LISTING → CALL_AUCTION(10분) → LISTED`

- **PRE_LISTING**: 현물 거래가 불가능하고 채굴 잔고는 쌓이기만 합니다. **채굴량 선물만** 거래할 수 있습니다.
- 관리자가 **상장 버튼**을 누르면 10분 동안 현물 **지정가 주문만** 모읍니다. 이 동안 호가창에 예상 체결가와 수량이 표시됩니다.
- 시간이 끝나면 **단일가**로 체결합니다. 체결 수량이 최대인 가격을 고르고, 동률이면 잔량이 최소인 가격, 그다음은 매수 초과면 높은 가격·매도 초과면 낮은 가격을 고릅니다. 이후 연속 매매가 시작되고 무기한 선물도 열립니다.

### 4. 현물 (PIKU/KRW)
- 지정가, 시장가(매수는 총액, 매도는 수량)를 지원합니다. 가격-시간 우선으로 매칭하며 체결가는 메이커 가격입니다.
- 자전거래 방지: 내 주문끼리 만나면 기존 메이커 주문을 취소합니다.
- 더 싼 가격에 체결되면 묶어 둔 매수 대금의 초과분을 즉시 풀어 줍니다.
- 호가창과 체결은 WebSocket으로 실시간 갱신됩니다. 캔들은 1분·5분·15분·1시간·4시간·1일입니다.

### 5-1. 채굴량 선물 (상장 전부터)
- 계약 내용은 "만기일까지 PIKU N개를 가격 P에 인도"입니다. 월물 만기는 **매월 마지막 금요일 15:00 KST**이고, 3개 월물이 동시에 열리며 **월물마다 호가창이 따로** 있습니다.
- 매도자는 채굴자입니다. **매도 한도 = 확정 잔고 + 만기까지 예상 채굴량 × 70% − 이미 약정한 수량**이고, 예상 채굴량은 최근 7일 평균 해시레이트로 계산합니다.
- 증거금은 매수자 20%, 매도자 10%(KRW)이고, 체결되는 즉시 계약으로 옮겨집니다(에스크로).
- **만기 정산**은 체결 순서대로 처리합니다.
  1. 인도 가능 수량 d = min(N, 매도자 코인 잔고)
  2. 매수자는 d × P를 증거금 → 가용 KRW 순서로 지불합니다. 잔금을 낼 수 없으면 매수자 불이행으로 처리해 매수자 증거금을 매도자에게 줍니다.
  3. 부족분 s = N − d가 있으면 **매도자 증거금 × s/N을 몰수해 매수자에게 보상**하고 나머지는 반환합니다.
- 인도 의무가 있는 수량은 **현물 매도와 출금이 막힙니다**.
- 만기 전 중도 청산(반대매매)은 지원하지 않습니다. 실물 인도까지 보유하는 구조입니다.

### 5-2. 무기한 선물 (상장 후)
- **마크 가격** = 현물 (최우선 매수호가, 최우선 매도호가, 최근 체결가)의 중앙값
- 레버리지 1~10배, **격리/교차** 마진을 지원합니다. 시장가는 마크가 ±10% 보호가격을 적용하고, '시장가 종료'는 reduce-only로 동작합니다.
- **펀딩비**는 8시간마다 정산합니다. 비율 = clamp((선물 중간가 − 마크가) / 마크가, ±0.75%)이고, 양수면 롱이 숏에게 냅니다.
- **강제청산** 조건은 다음과 같습니다(유지증거금률 0.5%).
  - 격리: 증거금 + 미실현손익 < 유지증거금
  - 교차: 가용잔고 + Σ증거금 + Σ미실현손익 < Σ유지증거금. 청산 전에 미체결 주문을 먼저 취소해 담보를 확보해 봅니다.
- **보험기금**이 청산 포지션을 마크가로 인수합니다. 남은 가치에서 청산 수수료(0.5%)를 적립하고, 파산(가치 음수)이면 손실을 보전합니다. 인수한 포지션은 호가가 보호 범위 안에 있을 때 자동 정리하고, 보험기금이 음수가 되면 알림을 남깁니다.
- 화면에 포지션, 진입가, 마크가, **청산가**, 미실현 손익(ROE), 실현 손익, 펀딩 내역이 표시됩니다.

### 6. 계정/보안
- 회원가입 후 이메일 인증을 거칩니다. 테스트 모드에서 SMTP가 없으면 자동 인증되고 링크는 콘솔에 출력됩니다.
- **TOTP 2FA**(RFC 6238, 직접 구현, 코드 재사용 방지)를 지원하고, **출금 시 2FA는 필수**입니다.
- **KYC는 인터페이스만** 제공합니다(`backend/src/lib/kyc.ts`의 `KycProvider`). 테스트 모드는 자동 승인되고, 실자금 모드에서는 KYC 승인 전에 거래와 출금이 막힙니다.
- **감사 로그**: 주문, 체결, 취소, 입출금, 로그인, 관리자 조작, 청산, 펀딩, 만기 정산, 블록 발견을 모두 `audit_logs`에 기록합니다. DB 트리거로 **수정/삭제를 금지**합니다.
- 모든 잔고 변경은 `ledger_entries`(원장)에 남습니다. `balances`의 CHECK 제약으로 음수 잔고는 DB 수준에서 불가능합니다(보험기금과 수수료 계정만 예외, 대신 알림으로 감시).

### 7. 관리자 페이지
- 상장 단계 전환(상장 시작, 콜옥션 즉시 종료), 마켓 일시정지/재개를 할 수 있습니다.
- 출금 승인 큐(관리자 OTP 확인), 거절과 종결을 처리합니다.
- 풀 수수료, PPLNS 창, 컨펌 수, 선물 증거금, 매도 한도 비율, 레버리지, 유지증거금률, 펀딩 상한 등 파라미터를 수정할 수 있습니다. 범위를 검증한 뒤 엔진에 즉시 반영합니다.
- 사용자별로 **운영자 플래그(자사 코인 거래 금지)**, 거래 정지, KYC 상태를 바꿀 수 있습니다.

## 실자금 모드 전 확인사항

`REAL_MONEY_MODE=true`로 켜면 다음이 모두 있어야 기동됩니다: 32자 이상의 `JWT_SECRET`, `VASP_REGISTRATION_NO`, `LEGAL_REVIEW_ACK=I_HAVE_LEGAL_APPROVAL`, `SMTP_HOST`. 또한 실자금 모드에서는 KYC 승인 전 거래와 출금이 막히고, 가상 KRW 지급과 충전이 비활성화되며, CORS가 `APP_URL`로 제한됩니다.

하지만 **설정 플래그로는 법적 요건을 충족할 수 없습니다.** 국내 기준으로 반드시 전문가 검토가 필요한 쟁점은 다음과 같습니다(법률 자문이 아닌 체크리스트입니다).

1. **가상자산사업자 신고**(특정금융정보법): ISMS 인증, 원화 마켓은 은행 실명확인 입출금계정, 자금세탁방지(AML/트래블룰) 체계가 필요합니다.
2. **자기 발행 코인의 매매·중개 제한**: 특정금융정보법 시행령과 가상자산이용자보호법은 사업자 본인이나 특수관계인이 발행한 가상자산의 거래를 제한합니다. **"내가 만든 코인을 내 거래소에 상장"하는 이 프로젝트의 기본 구조가 그대로는 허용되지 않을 수 있습니다.** 운영자 거래 금지 플래그만으로는 해결되지 않습니다.
3. **파생상품**: 무기한 선물과 채굴량 선물(상장 전 판매 포함)은 자본시장법상 파생상품이나 증권(투자계약증권)에 해당할 수 있습니다. 국내 가상자산사업자가 파생상품을 제공하는 것은 현재 허용되지 않는 것으로 알려져 있습니다.
4. **이용자 자산 보호**: 예치금 분리 보관, 콜드월렛 보관 비율, 보험이나 준비금, 해킹 사고 대응 계획이 필요합니다. 이 코드는 노드 지갑 하나를 핫월렛으로 쓰며 **콜드월렛 분리가 없습니다**.
5. **불공정거래 감시**: 시세조종, 자전거래 탐지와 이상거래 모니터링, 보고 체계가 필요합니다.

## 알려진 제약 (실서비스 전 보완 필요)

- 매칭 엔진은 의도적으로 단일 인스턴스입니다(수직 확장만 가능). 장애 시 재시작하면 ACK되지 않은 명령을 주문 ID 기준으로 멱등 재처리하지만, 고가용성(대기 엔진 자동 승격)은 없습니다.
- 거래 수수료(메이커/테이커)가 없습니다.
- TOTP 비밀키가 DB에 평문으로 저장됩니다(KMS 암호화 권장). 웹 로그인 토큰은 localStorage에 있어 XSS에 취약하므로 httpOnly 쿠키 전환을 권장합니다.
- 보험기금 인수 방식은 단순화된 모델입니다. 자동 디레버리징(ADL)은 없고, 보험기금이 고갈되면 음수 허용 + 알림으로 처리합니다.
- 교차 마진은 무기한 마켓이 하나라는 전제로 계산합니다.
- 핫월렛 대사는 노드 지갑 전체를 기준으로 합니다(콜드월렛 없음).
- 캔들은 체결 테이블을 SQL로 집계합니다. 거래량이 커지면 사전 집계 테이블이 필요합니다.
- Docker 이미지는 이 저장소의 개발 환경에서 레지스트리 제한 때문에 끝까지 빌드해 보지 못했습니다. compose 구성 검증(`docker compose config`)과, 같은 빌드 산출물(`node dist/...`)로 4개 프로세스를 기동하는 것까지는 확인했습니다.
